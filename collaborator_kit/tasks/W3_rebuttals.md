# Task W3 - Reviewer-Attack Rebuttals

## Goal

Draft internal one-paragraph rebuttals for each S-tier and A-tier reviewer
concern in `REVIEWER_ATTACK_MAP.md`.

This is not paper prose. It is response-prep material for the review period.

## Inputs

- `REVIEWER_ATTACK_MAP.md`.
- Current paper draft, if available.
- Appendix task notes/results available at the time.
- Your fresh read of the code and claims.

## Deliverable

Create `rebuttals.md` with one section per concern:

```markdown
## S1: y_expert is not a real expert signal

Reviewer concern:

Response:

Evidence to cite:

Weakness / caveat:

Action before submission:
```

Use the same template for S1-S4 and A1-A4.

## Rules

- Be direct. A rebuttal that depends on a weak assumption should say so.
- Separate evidence from rhetoric.
- Prefer "we measure X in Table Y" over broad claims.
- If the best response is "this is a limitation", write that.

## Success criteria

- `rebuttals.md` exists.
- Every S-tier and A-tier concern has a filled template.
- Open weaknesses are clearly marked.
- No experiments are blocked on this task.
